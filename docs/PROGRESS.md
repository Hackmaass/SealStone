## P09 Attack Lab (2026-10-11)
- `/attack-lab`: 12 attacks + 1 contrast, each a REAL call from the sandbox accounts (#3 attacker, #4 client, #5 provider, #6 arbiter). Engine and catalogue are React-free in `lib/attacks.ts` (steps are setup / attempt / check); `ui/AttackRow.tsx` + `pages/AttackLab.tsx` draw it like the prototype (stars, cursor row, stamped verdicts, red-tinted contrast).
- **Deviation from the prompt (on purpose):** instead of two shared sandboxes, EVERY attack deploys its own fresh 3-milestone vault. Rows are independent (Run works alone), "Run all" is trivially idempotent (it also clears the table first), and no row can be fooled by a previous row's leftovers. The demo vaults are never touched; the e2e proves it by comparing the seeded vault's events, milestone state, balance and code before and after 39 sandbox runs.
- Honesty rules: three outcomes (pass = matched expectation, FAILED = the contract did something else, Lab error = the lab could not finish; only pass counts as blocked). The score is computed from the results, never hard-coded. Refused calls are shown as "refused before it was mined: no transaction, no gas". The re-entrancy row sends an explicit gas limit (estimation finds the minimum gas, where a re-entry could fail by running out of gas instead of by the guard) and asserts the guard's own error (`ReentrancyGuardReentrantCall` decoded from `lastRevertSelector`), attempts >= 1, blocked == attempts, succeeded == 0, the payout is exactly the 1.000 ETH owed and nothing remains owed. ## Known issues
- `extract` grounds/validates against the first 6,000 characters of the text, but the gate and `sourceTextHash` use the FULL text, so for agreements over 6k characters the gate can require flags the extract response never showed. Design answer (P07): drive the cards and the Confirm button from `/api/gate-check`, not from `/api/extract`.
- With a live LLM, AI false-positive flags (e.g. `UNDEFINED_TRANSITION:2:0` from qwen2.5:7b) must be resolved by a human; the validator never removes an AI flag. Only rules mode + the sample's resolutions reproduces the pre-seeded vault's agreement hash.
- Cold Ollama call took 26.8 s vs the 30 s timeout; extraction can take ~60 s with a retry. Consider a warm-up call at server start (P11).
- P06 is blocked on the teammate's 7 sample agreements + `samples/expected.json` (docs/07); only the builder-draft `krishilens.txt` exists.
